ในเว็บไซต์แล้ว

ปรับระบบความปลอดภัย การบันทึกผลตามบาส 3×3 การป้องกันข้อมูลสูญหาย และการแจ้งข้อผิดพลาดแล้ว มีขั้นตอนตั้งค่าแอดมินและ deploy ที่ต้องทำก่อนเปิดใช้งานจริง

หน้าตาและโครงสร้างดี · มือถืออ่านง่าย มีทางลัดหลักครบ
แก้แล้วบัญชีตัวอย่าง · validation · SSE · migrations
ต้องทำก่อนเปิดใช้ตั้งค่า secret, สร้างแอดมิน และตั้ง persistent storage

เสร็จ · ความปลอดภัย

เอาบัญชีเริ่มต้นออกและป้องกัน session

เอา admin/admin123 ออกจากหน้า Login และ seed ใช้ HttpOnly cookie, อายุ 8 ชั่วโมง, จำกัดการลอง login และบังคับตั้ง JWT secret ที่มีความยาวเหมาะสม

  • สร้างบัญชีแอดมินเองผ่าน environment variables
  • จำกัด CORS ด้วย allowlist เมื่อเป็น production
  • เพิ่ม Helmet และจำกัดขนาด request body
เสร็จ · ความถูกต้องของการแข่งขัน

ทำให้ข้อมูลคะแนนตรงกับกติกา 3×3

seed ใหม่สร้างตาราง 24 ทีมและ 36 เกมรอบแบ่งกลุ่มในสถานะ upcoming ไม่มีผลคะแนนปลอม ตรวจคะแนน 3×3 และไม่แปลงข้อมูลควอเตอร์เก่ามาเป็นสถิติการยิง

ตามคู่มือ FIBA 3×3 เกมปกติเล่น 10 นาที ทีมแรกที่ถึง 21 แต้มชนะ และต่อเวลาชนะเมื่อทำเพิ่มได้ 2 แต้ม อ่านคู่มือ FIBA
เสร็จ · ฐานข้อมูลภายนอก

Render Free ใช้ PostgreSQL ผ่าน Prisma

render.yaml ตั้งค่า Render Free ให้ต่อ PostgreSQL ภายนอก ไฟล์ SQLite ไม่ถูกใช้ใน production และข้อมูลจึงไม่ผูกกับ filesystem ที่ถูกล้างเมื่อ Render deploy หรือ restart

  • ตั้ง DATABASE_URL แบบ pooled และ DIRECT_URL แบบ direct ใน Render Dashboard
  • ฐานข้อมูลฟรียังมีเพดาน quota; เมื่อใช้ครบอาจหยุด query ชั่วคราว แต่ข้อมูลคงอยู่

ตรวจเพิ่มก่อนเปิดใช้งานจริง

สำคัญ · ประสบการณ์ผู้ใช้

ตั้งค่าความลับและสร้างบัญชีผู้ดูแล

คัดลอก server/.env.example เป็น server/.env แล้วตั้ง JWT_SECRET, ADMIN_USERNAME, ADMIN_PASSWORD จากนั้นรัน migrations, seed และ npm run admin:create

สำคัญ · ตารางคะแนน

ย้ายข้อมูล SQLite เดิมก่อน deploy ครั้งแรก

รัน prisma:migrate:deploy กับ PostgreSQL ปลายทางที่ว่าง แล้ว npm run db:import-sqlite เพื่อเก็บทีม, แมตช์, ข่าว, admin และ IDs เดิม ก่อน deploy Render ครั้งแรก

สำคัญ · คะแนนสด

รัน build และตรวจหน้าจอจริง

ยังไม่ได้รัน test suite หรือยืนยัน end-to-end กับฐานข้อมูลจริงในรอบแก้ไขนี้ ให้รัน build และตรวจ login, บันทึกคะแนน, ผลและ standings ใน environment ที่ตั้งค่าแล้ว

ควรทำ · ความเสถียร

เกมรองและเกมชิงไม่ผูกกับทีม placeholder และการลบทีม/ย้ายกลุ่มถูกปฏิเสธเมื่อจะทำลายประวัติการแข่งขัน

ควรทำ · แพ็กเกจ

มีข้อความ error และอัปเดตหน้าอัตโนมัติ

หน้าสาธารณะและหน้าจัดการแสดง error พร้อมปุ่มลองใหม่ และใช้ Server-Sent Events เพื่อโหลดข้อมูลล่าสุดหลัง admin เปลี่ยนข้อมูล

สิ่งที่ต้องทำโดยผู้ดูแลระบบ

ตั้งค่า .envกำหนด secret และบัญชี admin ที่เดายาก ห้ามเผยแพร่ไฟล์ .env
ตั้งค่า PostgreSQLใส่ DATABASE_URL, DIRECT_URL, ADMIN_USERNAME และ ADMIN_PASSWORD ใน Render Dashboard
คงข้อมูล SQLite เดิมใช้ migration และ db:import-sqlite ก่อน deploy ครั้งแรก; ฐานข้อมูลปลายทางต้องว่าง
ตรวจ end-to-end ใน stagingยืนยัน flow ผู้ดูแลและหน้าเว็บจริงก่อนประกาศใช้
หมายเหตุการตรวจและไฟล์อ้างอิง

การเปลี่ยนแปลงทำในโค้ด local ยังไม่ได้ deploy และไม่ได้รัน test suite ตามข้อกำหนดงาน ตรวจไฟล์ README และ USER_MANUAL สำหรับขั้นตอนตั้งค่าก่อนใช้งาน

หน้า Login การตั้ง JWT ข้อมูลตัวอย่าง ตั้งค่า Deploy คำสั่ง Build หน้าผลการแข่งขัน
